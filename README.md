## The problem

Ask an agent to make a Manim animation and three things go wrong:

1. **It invents API.** `ShowCreation` vs `Create`, `TexMobject` vs `MathTex`, `get_graph` vs
   `ax.plot` — the two Manim forks diverged, and half the tutorials on the internet describe a
   version that no longer exists.
2. **It can't find the output.** The path depends on `media_dir` × module name × quality ×
   `output_file`. Agents shell out to `manim`, then guess, then guess wrong.
3. **It doesn't know what's slow.** "Use the GPU" is not one thing. Manim has *two* independent
   expensive stages, and the popular advice conflates them.

This repo fixes all three, with everything verified against the actually-installed packages.

## Quick start

```bash
git clone https://github.com/frederico-kluser/manim-agent-skills.git
cd manim-agent-skills
bin/setup                    # ManimCE + manimx    (add --with-gl for ManimGL, --all for everything)
bin/mx doctor                # exit 0 = ready

bin/mx render scenes/exemplos.py OlaManim -q h --codec nvenc --json
```

```json
[{ "scene_name": "OlaManim", "success": true,
   "output_file": "/abs/path/media/videos/exemplos/1080p60/OlaManim.mp4",
   "codec": "h264_nvenc", "resolution": [1920, 1080], "elapsed_s": 2.41 }]
```

The output path comes from the `SceneFileWriter` itself. No guessing.

**Requirements:** Python ≥ 3.11 (ManimCE 0.21 needs it), plus LaTeX and `ffmpeg` if you want
`MathTex` and ManimGL. No GPU required — everything degrades to CPU. `bin/setup` tells you what's
missing instead of failing.

## GPU: what actually gets accelerated

A Manim render has **two independent expensive stages**. Conflating them is why "just use the GPU"
so often produces no speedup.

| Stage | Default | Accelerated by |
|---|---|---|
| **1. Rasterizing geometry** into frames | Cairo (CPU) | `--renderer opengl` (ModernGL) · ManimGL (wgpu/Vulkan) |
| **2. Encoding** frames into video | libx264 (CPU) | `--codec nvenc` (NVENC) |

Measured with `bin/mx bench` on an RTX 4070 Laptop, 1080p60, across several runs:

| Scenario | Time |
|---|---|
| encode-bound — cairo + x264 | ~5.0–5.7 s |
| encode-bound — cairo + **NVENC** | **~2.7–3.0 s** (≈ −45%) |
| geometry-bound — cairo + x264 | ~5.7–5.8 s |
| geometry-bound — cairo + NVENC | ~5.9–6.3 s (**no gain**) |
| geometry-bound — **opengl** + NVENC | ~5.1–5.4 s (≈ −10%) |

**NVENC's win on encode-bound scenes is large and consistent. On geometry-bound scenes it does
nothing** — there you need the renderer, and that gain is real but modest and noisy. Numbers vary
between runs; `bin/mx bench` measures *your* machine rather than asking you to trust these.

### Making NVENC work at all was the hard part

ManimCE **no longer shells out to `ffmpeg`**. Since v0.19 it drives **PyAV** directly, with the
codec hardcoded in `scene_file_writer.py` (`libx264`, `crf=23`). `config.ffmpeg_executable` was
deleted. Every "point ffmpeg at an NVENC wrapper" recipe on the internet is dead.

`manimx.gpu` solves it without touching Manim's internals: it intercepts `av.open` *only during*
`open_partial_movie_stream` and returns a proxy that rewrites `add_stream`. Since Manim's final
concat is a pure stream copy (`add_stream_from_template`), swapping the per-animation codec changes
the whole output file.

```python
from manimx import enable_nvenc
enable_nvenc(codec="hevc_nvenc", profile="quality")
```

ManimGL is the opposite — it still calls the `ffmpeg` binary, so it's one flag
(`--vcodec h264_nvenc`), which `bin/manimgl` injects automatically when an NVIDIA GPU is present.

## The API index

Generated by reflection over the **installed** packages (`bin/mx api-dump`), not scraped from docs —
which matters, because ManimCE's OpenGL classes (`OpenGLMobject`, `OpenGLRenderer`, …) have **no
pages at all** on the official docs site.

| File | What | Size |
|---|---|---|
| `api/manim-ce-index.tsv` | 1 symbol per line — **grep this** | 528 KiB |
| `api/manim-ce-methods.tsv` | 1 method per line, with class + signature | 6.8 MiB |
| `api/manim-ce-toplevel.md` | everything `from manim import *` gives you | 33 KiB |
| `api/manim-ce-by-category.md` | browsable by category | 570 KiB |
| `api/manim-ce-inheritance.txt` | inheritance tree | 6 KiB |
| `api/manim-ce-api.json.gz` | everything, structured (read by the CLI) | 1.4 MiB |
| `api/manimgl-*` | same, for ManimGL | |
| `api/ce-vs-gl.md` | compatibility map between the two forks | |

**Coverage:** 338 classes · 285 functions · 4,900 constants · 5,523 symbols total.
Inherited methods included — `Circle` alone indexes **264 methods** (4 its own, 260 inherited),
which is the point: an agent that only sees a class's own methods concludes the API is missing.

```bash
bin/mx find "transform" --kind class     # search by name, docstring, or method name
bin/mx show Circle                       # full signature + every method
bin/mx show Axes --own-only --json

# or just grep
awk -F'\t' '$1=="class" && $3 ~ /^animation/ {print $2}' api/manim-ce-index.tsv
```

## The 14 skills

| `manim-gpu-encoding` | NVENC, renderers, PRIME offload, benchmarking |
| `manim-mobjects` | shapes, positioning, groups, submobject trees |
| `manim-animations` | the full animation catalog, timing, composition |
| `manim-color-theming` | color, backgrounds, themes, alpha channel |
| `manim-text-latex` | Text/MarkupText/Tex/MathTex, coloring parts of a formula |
| `manim-graphs-plots` | axes, function plots, data, graph theory |
| `manim-3d-camera` | 3D scenes and camera movement |
| `manim-updaters-valuetracker` | reactive animation |
| `manim-troubleshooting` | symptom → cause → fix |
| `manimgl-3b1b` | ManimGL, and translating GL ↔ CE |
| `manim-batch-pipeline` | batch rendering, parallelism, CI |

Each one is written against *this* installation, with the gotchas verified rather than repeated
from blog posts.

## Corrections to the documentation everyone repeats

All verified on ManimCE 0.21.0 / ManimGL master. Tutorials from 2024–2025 get these wrong:

| Commonly claimed | Actually |
|---|---|
| `manim -c WHITE file.py Scene` sets the background | `-c` is now `--config_file`. **`--background_color` was removed.** |
| 3-digit hex (`#F00`) breaks the parser | Works — resolves to `#FF0000`. What breaks is hex *without* `#`. |
| Manim pipes frames to the `ffmpeg` binary | CE uses **PyAV** since 0.19; `config.ffmpeg_executable` is gone. |
| You can swap the codec via config in CE | You cannot — it's hardcoded. Hence `manimx.gpu`. |
| ManimGL is OpenGL | **master is wgpu/Vulkan.** The PyPI wheel is OpenGL. Both report `1.7.2`. |
| ManimGL's default background is black | It's `#333333`. |
| CE removed `--renderer=opengl` | It didn't — it got bug fixes in 0.21.0. |
| ManimCE runs on Python 3.8+ | Needs **3.11+**. On older Python, `pip` silently installs an ancient CE. |
| `pip install IPython==8.0.1` fixes interactive mode | 2022-era advice the official FAQ still repeats. Only if you actually hit the bug. |

Two encoder traps, both hit during development:

- **`profile=high` is H.264-only.** HEVC wants `main`; AV1 has no `profile` option and returns
  `EINVAL`. Because PyAV opens the encoder lazily *on the first frame*, this would blow up
  mid-render — so `manimx.gpu.validate_encoder()` round-trips a test encode **and remux** first.
  That's also how it catches AV1 being unusable here (the concat step needs a `libdav1d` *encoder*
  that doesn't exist), and falls back cleanly.
- **ffmpeg silently ignores `-crf` with NVENC.** No error, no warning — you just don't get the
  quality you asked for. Use `cq`.

## Layout

```
bin/setup              bootstrap from a clean clone
bin/mx                 the agent-facing CLI (JSON output)
bin/manim  bin/manimgl wrappers: LaTeX on PATH, GPU env, right venv
manimx/                the API layer
  gpu.py                 GPU detection + the NVENC patch
  render.py              programmatic rendering, real output paths
  presets.py             quality / codec / theme presets
  introspect.py          the API dumper
  apidiff.py             CE ↔ GL compatibility map
  bench.py               CPU vs GPU benchmark
  cli.py                 `mx`
tools/batch_render.py  multi-process batch rendering
tools/check_publishable.sh  pre-publish guard (secrets, paths, sizes)
scenes/                6 CE examples + 3 ManimGL examples
api/                   the generated index (committed on purpose)
.claude/skills/        the 14 skills
manim.cfg              ManimCE config      custom_config.yml   ManimGL config
pyproject.toml         `manimx` package    uv.lock
```

`media/` and `media-gl/` appear after your first render; they're gitignored.

## Batch rendering

```bash
.venv/bin/python tools/batch_render.py scenes/ -q h --codec nvenc -j 4 --json
```

Multi-process on purpose: Manim's `config` is a mutable global, so two scenes in one process
corrupt each other. Two failure modes this script already handles, both reproduced here:

- **LaTeX race.** Two workers compiling into the same `media/Tex` collide on `.aux` cleanup
  (`FileNotFoundError`), non-deterministically. Fixed by isolating `tex_dir` per worker — placed
  *outside* `media/Tex`, because Manim's cleanup does `for f in tex_dir.iterdir(): f.unlink()`
  without checking for directories, which would then break every later LaTeX render.
- **NVENC session limits.** Consumer GPUs cap concurrent encode sessions; 4 workers verified here.

## Maintenance

```bash
VIRTUAL_ENV=.venv    uv pip install -U manim
VIRTUAL_ENV=.venv-gl uv pip install -U "manimgl @ git+https://github.com/3b1b/manim.git"
bin/mx api-dump && bin/mx api-diff     # the index must follow the install
bin/mx doctor
```
